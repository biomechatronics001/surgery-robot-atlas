Ways to contribute

Add a robot

Any robot that pushes or twists a catheter or guidewire, or a device that bends its own tip, with at least one paper or product page. Open an issue with the form below, or send the YAML file as a pull request.

Fix a record

A wrong number, a missing version, a newer test level: change the field, cite the source key and section in the text, open a pull request. Every robot page has a "Suggest a correction" link.

Give a picture

A photo of your own robot under CC BY 4.0 replaces a placeholder. State the licence and the credit line you want.

Improve the schema

Need a field or a vocabulary value that does not exist? Propose it in the same pull request as the record that needs it.

Add or fix a record

  1. Copy the template below to records/robots/<id>.yaml. The id is <shortname>_<firstauthor><year> in lower case, e.g. legobot_gao2026.
  2. Fill the fields from the papers. Required: schema_version, id, name, full_name, group, family, category, first_year, devices, translation_mechanism, rotation_mechanism, highest_validation, sim2real, picture, sources, read_level, maintainers_own. Vocabularies are listed in the docs.
  3. Validate: python3 tools/validate_records.py (needs pip install pyyaml jsonschema). It exits non-zero and names the file and field on any error.
  4. Preview: python3 tools/build_site.py --public, then cd site && python3 -m http.server 8000 and open http://localhost:8000.
  5. Submit a pull request with the YAML file (and a picture in records/pictures/ if you own it). The repository's checks run the validator and build the site.

While the catalogue is generated from the review's CSV, a maintainer copies an accepted change into the CSV, so it survives the next build.

Field rules

  • Write what the source says, in its units, with the source key and section: stroke 300 mm (kantu2025_portable Sec. III-A).
  • A number the source does not report is N.R.. Never estimate or convert a number the source did not give.
  • One record per robot line: later versions of the same robot go into versions, oldest first.
  • highest_validation is the highest level reached by any version, and validation_detail says how many cases, animals or patients.
  • sim2real is yes only when a controller or model trained in simulation ran on this robot; cite the study.
  • read_level says honestly how deep the reading went: full text, part of it, abstract, web page, or a secondary source.
  • Every paper in sources has its DOI when one exists.

Pictures

A picture is published only when its licence allows reuse: Creative Commons Attribution (CC BY, without NC, ND or SA) or material of the maintainers' own lab; the rule is licence_ok() in tools/licence_rule.py. Any other picture (publisher copyright, press images, NC/ND licences) stays at its source and the record links to it. Pictures are resized to 800 px on the long side; list every change you made in picture.edits (CC BY asks for that).

Pull request checklist

  • One robot per file; file name = id + .yaml.
  • python3 tools/validate_records.py passes.
  • Every number has its source key and section; unreported values are N.R..
  • Every source has a DOI or a link.
  • A picture, if added, is yours or CC BY, with licence, credit and edits filled.
  • If you built the robot, say so in the pull request.
